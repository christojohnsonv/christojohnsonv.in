01 / About

Backend by trade. Systems by instinct.

I enjoy the part of software engineering where application behaviour meets data, infrastructure and real-world constraints.

I'm an Associate Technical Lead and backend engineer focused primarily on Python and Go. My experience spans API platforms, financial services, network-management systems, analytics pipelines and production backend infrastructure.

Over time, my work has moved beyond implementing individual features toward understanding the system around them: service boundaries, data models, database behaviour, asynchronous processing, performance and operational reliability.

I prefer simple systems where possible, and deliberate complexity where the workload actually requires it.

Measure before tuning

Build for operation

03 / Engineering

The problems I like solving.

Technology changes. These are the engineering problems that remain interesting.

01

APIs & Services

Designing clear service interfaces, authentication, communication patterns and APIs that can evolve without becoming difficult to maintain.

02

Data & Performance

Understanding how data moves through a system, then improving the parts that actually limit performance: queries, indexes, caching and processing paths.

03

Distributed Systems

Background work, messaging, service-to-service communication, concurrency and the failure modes that appear once systems stop running as a single process.

04

Production Systems

Linux, containers, deployment, logging, metrics and the operational details required to keep backend services useful after they leave development.

05

Reliability

Designing around retries, timeouts, idempotency, validation, safe data changes and graceful failure rather than assuming everything will always work.

06

Technical Leadership

Turning requirements into technical decisions, reviewing implementation choices and helping engineers build systems that are easier to operate and evolve.
